# Как здесь пишут код

Проект разложен по слоям: `Domain` → `Application` → `Persistence` → `Web`, плюс `*.Contracts`
с интерфейсами и DTO. Ссылки идут только внутрь: `Web` знает про `Application.Contracts`,
но не наоборот.

## Общее

- Целевая платформа — net10.0, `Nullable` и `ImplicitUsings` включены, предупреждения = ошибки.
- Имена на английском, комментарии и сообщения пользователю — на русском.
- Комментарий объясняет «почему», а не «что». Пересказ кода словами не нужен.
- Публичные типы и методы, которые кто-то будет читать снаружи, снабжаются `<summary>`.

## Domain

- Сущности с приватными сеттерами и приватным конструктором для EF.
- Создание — через статический `Create(...)`, изменение — через методы с осмысленными именами
  (`Rename`, `Pin`, `SetError`), а не через присваивание свойств снаружи.
- Параметры конструирования — отдельные record-параметры (`CreateConversationParameter`),
  а не длинный список аргументов.
- Идентификаторы — `Guid.CreateVersion7()`, чтобы они были монотонными и не рвали индекс.

## Application

- Один хендлер — один файл, класс помечается `file sealed class`.
- Результат — `Result<T>` из `Domain.Common`, а не исключения на бизнес-ошибки.
- Ошибки — через фабрики `Error.NotFound`, `Error.Conflict` и т.д. с кодом вида `Chat.NotFound`.
- Хендлер не ходит в `DbContext` напрямую — только через репозитории из `Persistence.Contracts`.

## Persistence

- Конфигурации сущностей — отдельными классами `IEntityTypeConfiguration<T>`.
- Именование в БД — snake_case (за это отвечает `EFCore.NamingConventions`).
- Любое изменение модели сопровождается миграцией; руками SQL не пишем.

## Ассистент

- Слой `Application` разговаривает с моделью только через `IAssistantAgent`.
- Про `Microsoft.Agents.AI`, сессии и `IChatClient` знает только проект `Assistant`.
- Новые возможности агента добавляются провайдером контекста, а не свалкой в системном промпте.
